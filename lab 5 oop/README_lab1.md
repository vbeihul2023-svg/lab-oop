## 1. Основи роботи з pip

### Перевірка pip та встановлені бібліотеки
Команда `pip -V` показала версію pip встановлену в системі.
Команда `pip list` вивела список встановлених бібліотек.

**📸 [ВСТАВИТИ СКРІНШОТ: результат pip list]**

### Встановлення та тестування requests
```
pip install requests
```

### Зміна версії та видалення
```
pip show requests     → показала інформацію про бібліотеку
pip install requests==2.1  → встановила стару версію
pip show requests     → показала версію 2.1
pip uninstall requests → видалила бібліотеку
```

## 2. Робота у віртуальному середовищі (venv)

Після команди `deactivate` та `pip show requests` — нічого не вивелось, тому що:
> Бібліотека requests була встановлена лише у віртуальному середовищі `my_env`. Після виходу з нього (`deactivate`) команда `pip` використовує глобальний інтерпретатор, де requests не встановлено.

**Папки для .gitignore:**
```
my_env/
__pycache__/
.env
```

## 3. Робота з Pipenv

### Доступні команди pipenv:
- `pipenv install` — встановити залежності
- `pipenv shell` — активувати середовище
- `pipenv run` — запустити команду в середовищі
- `pipenv graph` — дерево залежностей
- `pipenv check` — перевірка вразливостей
- `pipenv --rm` — видалити середовище

### Файли Pipfile та Pipfile.lock:
- **Pipfile** — містить список залежностей проекту та версію Python
- **Pipfile.lock** — містить точні версії всіх залежностей та їх хеші для відтворення середовища

### Результат flake8
flake8 знайшов помилки стилю коду (зайві пробіли, відсутній рядок в кінці файлу). Після виправлення повторний запуск не показав помилок.

**📸 [ВСТАВИТИ СКРІНШОТ: результат flake8]**

### Змінні середовища
Якщо виконати скрипт без активації середовища — отримаємо `KeyError: 'IT_TEST'`, тому що pipenv не завантажив `.env` файл.
